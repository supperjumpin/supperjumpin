# Local-First Auth with Internal Accounts

Supperjumpin uses local-first authentication for MVP development. The Go backend maintains an internal Account and Player model with a static bearer token (`SUPPERJUMPIN_DEV_AUTH_TOKEN`, defaults to `dev-token`) that exercises signed-in flows end-to-end — the local Docker Postgres API runs as a complete game server with no external dependencies. When hosted authentication is introduced, it will be additive: external auth provider identities may attach to Accounts without redefining in-game Player identity, Jump ownership, or Open standings. The local dev token remains the development path regardless of which hosted providers are added.
